LoanCalculator — redesign prototypes

The approved structure, built out. Read NAVIGATION-PROPOSAL.md for what changed and why. These pages are clickable — the bottom bar, the sub-tabs and the scenario rows all work, so you can walk the structure rather than judge it from stills. Compare against the 17 PNGs in ../screenshots/, captured from the running app at this same 390pt width.

Still prototypes: static figures, no calculation, no business logic. Dark theme only — all four themes share an identical token set, so the others follow mechanically. Token reference sheet ›

1 · Loan

What you're buying and borrowing. Running Cost has moved out to Budget; Amortisation has moved to What If — so this is now a single purposeful screen with no sub-tabs.

2 · Budget

Every recurring figure in one place. "Asset costs" is the old Loan ▸ Running Cost tab, relocated because it is a monthly outflow like any other. This is the one destination that keeps a sub-tab strip, because its views are genuine peers.

3 · What If

The headline change: nine What-If scenarios become a list with headline deltas instead of a nine-screen scroll, and each scenario gets its own page. Four sub-views instead of one scroll with buried rows: the Answer leads, Scenarios is the index that replaces the nine-screen scroll, and Projection and Insights (the additive half of Insights) get real presence rather than third-level rows.

4 · Settings

Same content, labelled once instead of twice.

Launch

Outside the tab structure. The splash is deliberately shown at its resting state — it has no entrance or exit animation, and that is load-bearing, not an omission.

Tablet

The app ships on iPad and none of this had been seen at that width. These use the real Tablet token column (body text 12→18, hero amount 18→32, chart height 250→350) and re-layout rather than stretch: What If becomes master–detail so the scenario drill-down disappears entirely, Settings becomes a sidebar plus detail pane, and Schedule drops the phone's decade grouping because the full table finally fits. The bottom bar becomes a left rail — at 768px tall, vertical space is the scarce axis.

Known gaps

The What If empty state has no screenshot to compare against: deleting data clears the loan JSON but deliberately leaves the live form populated, so that panel is only reachable on a fresh install. whatif-empty.html is built from the XAML instead. The PDF document is out of scope by request — export.html is the in-app screen that precedes it, not the report.
